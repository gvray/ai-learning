语法篇埋过一个伏笔：`[1,2,3] * 2` 得 `[1,2,3,1,2,3]`，`np.array([1,2,3]) * 2` 得 `[2,4,6]`。后者的逐元素运算，加上底层的连续内存，就是 NumPy 的全部价值所在。ML 里张量运算动辄百万次乘加，用 Python 循环写一秒都嫌慢，NumPy 把这些循环推到 C 层一次算完。本篇讲清 shape、广播、向量化——这三个概念贯穿后续所有 ML 库（PyTorch 的 Tensor 几乎是 NumPy 的 GPU 版）。

## 为什么是 NumPy：向量化 + 连续内存

Python `list` 存的是对象指针，每个元素单独寻址、单独类型。算 `[a[i]+b[i] for i in range(n)]` 要 n 次 Python 层解释开销。NumPy 的 `ndarray` 把同类数据**连续平铺**在内存里，运算走 C/Fortran 编译好的循环：

```python
import numpy as np
a = np.arange(1_000_000); b = np.arange(1_000_000)
c = a + b          # 一次 C 层循环，比 [x+y for x,y in zip(a,b)] 快几十倍
```

这就是**向量化**：不写 `for`，用整体表达式描述"对每个元素做什么"，让 NumPy 在底层批量执行。后续 PyTorch、Pandas 的运算模型都继承自这套思路——读 ML 代码，看到 `a + b`/`a * b` 默认就是逐元素。

## 创建数组与 dtype

```python
np.array([1, 2, 3])              # 从 list 建
np.zeros((3, 4))                 # 全 0，shape (3,4)
np.ones((2, 3))
np.arange(0, 10, 2)              # [0,2,4,6,8]，半开区间
np.linspace(0, 1, 5)             # [0, 0.25, 0.5, 0.75, 1.0]，均分含两端
np.random.randn(3, 3)            # 标准正态分布
```

每个 ndarray 有个 **dtype**——元素的数据类型。NumPy 的内存紧凑靠它：整块内存按同一类型排布，不存每个元素的类型标签。

```python
a = np.array([1, 2, 3])          # dtype int64（64 位整数，占 8 字节/元素）
a.dtype                          # dtype('int64')
a.astype(np.float32)             # 转成 float32（深度学习默认精度，省显存）
a.astype(np.int8)                # int8，但 127+1 会溢出回绕成 -128
```

dtype 是 ML 显存/内存的关键旋钮：`float32` 比 `float64` 省一半空间、快一倍，训练几乎都用 `float32`/`bfloat16`。但 NumPy 创建数组默认 `float64`——从 NumPy 跨进 PyTorch 时常常要 `.astype(np.float32)` 转一道，否则显存翻倍。

## shape 与 reshape

`shape` 是每个维度的长度元组，ML 里读代码一半时间在看 shape 对不对得上。

```python
a = np.arange(12)
a.shape                          # (12,)
a.ndim                           # 1（维数）
a.size                          # 12（元素总数）

b = a.reshape(3, 4)              # 改成 (3,4)，不复制数据、返回视图
b.shape                          # (3, 4)
a.reshape(2, -1)                 # -1 表示"自动推断"：12/2=6 → (2, 6)
```

`reshape` 改的是形状视图，**不改底层数据也不复制**（前提是内存连续）。`-1` 让 NumPy 算那一维，ML 里 `reshape(-1)` 把任何张量摊平成一维很常用。

shape 对不上是 ML 最常见的 bug 来源：

```python
x = np.random.randn(100, 32)     # 100 个样本，每个 32 维
W = np.random.randn(16, 32)      # 想映射到 16 维
x @ W.T                          # (100,32) @ (32,16) → (100,16)，矩阵乘用 @
x @ W                            # 报错 (100,32)@(16,32) 维度不匹配
```

养成习惯：写矩阵乘前先在脑里过一遍 `(a,b) @ (b,c) → (a,c)`，shape 不匹配 NumPy 会直接报错，PyTorch 同样——这套心智模型一次学到处用。

## 索引与切片：视图 vs 副本

语法篇提过 NumPy 切片是视图。这里讲全：三类索引，**返回视图还是副本决定改了会不会污染原数组**，是数据处理的隐形地雷。

```python
a = np.arange(12).reshape(3, 4)

# 1. 基本切片 → 视图（改了会动原数组）
row = a[1, :]                    # 第 1 行，视图
row[0] = 99                      # a[1,0] 也变成 99！

# 2. 布尔索引 → 副本
mask = a > 5
b = a[mask]                      # 所有大于 5 的元素，副本，改 b 不动 a

# 3. 高级索引（整数列表/数组）→ 副本
c = a[[0, 2]]                    # 第 0、2 行，副本
```

要安全地改一片数据、不污染原数组，显式复制：`copy = a[1, :].copy()`。`.copy()` 比事后排查"数据怎么被改了"便宜得多。

广播是 NumPy 最强大的特性，也是最容易静默出错的地方。

## 广播：不同 shape 怎么一起算

广播让不同 shape 的数组一起运算：小的那个在缺的维度上"复制扩展"，对齐后再算。规则只有两条：

1. 从右往左逐维对齐 shape，维度不同则把小的那个在左边补 1
2. 某维一个是 1 一个是 N，那个 1 当成 N 参与运算

```python
a = np.array([[1, 2, 3],           # shape (2, 3)
              [4, 5, 6]])
mean = np.array([2.0, 3.5, 5.0])   # shape (3,)  → 对齐成 (1,3) → 扩展成 (2,3)
a - mean                           # 每行减去 mean，shape (2,3)
```

减均值、批归一化、给所有样本乘一个权重——ML 里到处是"一个向量作用到整个 batch"的模式，全靠广播。没广播你得写循环或 `np.tile` 手动扩。

但广播会**静默扩展**，shape 本该相等却因广播"歪打正着"算出意外的 shape，bug 不报错：

```python
a = np.random.randn(100, 32)
b = np.random.randn(100)          # 想给每个样本加一个偏置，本该 (100,1)
a + b                             # 广播成 (100,32)+(100,1)? 不是！
# 实际：(100,32) 与 (32,) 对齐 → b 被当成"每列加一个值"，shape 仍 (100,32) 不报错
# 修正：b.reshape(100, 1) 或 b[:, None]
```

`b` shape `(100,)` 不会按你想要的"列向量"广播，得显式加一维 `b[:, None]` 或 `b.reshape(-1,1)`。广播出错 NumPy 通常不报错——养成"算完先看 `result.shape` 对不对"的习惯。

## 向量化与 axis 聚合

向量化是"别写 for"。axis 是聚合时"沿哪个维度消掉"：

```python
a = np.random.randn(100, 32)      # 100 样本 × 32 维

a.mean()                          # 标量：所有元素均值
a.mean(axis=0)                    # shape (32,)：沿 axis=0（样本维）消掉，每维的均值
a.mean(axis=1)                    # shape (100,)：沿 axis=1（特征维）消掉，每个样本的均值
a.sum(axis=0, keepdims=True)      # shape (1,32)：消掉但保留维度，便于继续广播
```

`axis` 是"沿这一维折叠"——`axis=0` 塌掉第 0 维。`keepdims=True` 保留那维为 1，结果还能和原数组广播，归一化常用：`(a - a.mean(axis=0, keepdims=True)) / a.std(axis=0, keepdims=True)`。

## 常见误区

- **`reshape` 不复制** → 拿到的是视图，改了动原数组；要独立数组用 `.copy()`。
- **切片是视图、高级/布尔索引是副本** → 改切片会污染原数据，分不清就全 `.copy()`。
- **广播静默扩展** → shape 本该相等却"歪打正着"算出意外结果，不报错。算完查 `result.shape`。
- **`(100,)` 当列向量** → 不会按 `(100,1)` 广播，用 `b[:, None]` 或 `b.reshape(-1,1)`。
- **默认 `float64`** → 跨进 PyTorch 前记得 `.astype(np.float32)`，否则显存翻倍。
- **`int8` 溢出回绕** → `np.array([127], dtype=np.int8) + 1` 得 `-128`，不报错。
- **`a * b` 不一定是矩阵乘** → 逐元素乘用 `*`，矩阵乘用 `@` 或 `np.matmul`，混了会算出完全错的结果（且不报错）。

## 小结

- NumPy 的价值是向量化（循环推到 C 层）+ 连续内存（dtype 平铺），ML 里张量运算全靠这套。
- shape 是 ML 代码的主线，写矩阵乘前先在脑里过 `(a,b)@(b,c)→(a,c)`。
- 三类索引：基本切片是视图（改了污染原数组），布尔/高级索引是副本；分不清就 `.copy()`。
- 广播强大但会静默扩展，算完必查 `result.shape`；`(n,)` 不是列向量，要 `[:, None]`。
- dtype 是显存旋钮：NumPy 默认 `float64`，跨 PyTorch 前转 `float32`。
