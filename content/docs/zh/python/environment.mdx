机器学习的依赖比普通项目更脆弱：PyTorch/NumPy/CUDA 版本相互耦合，本地 Apple Silicon、训练机 NVIDIA、同事 Windows 三套环境要跑同一份代码，实验还必须可复现。直接用系统 Python + `pip install` 乱装，迟早撞上"我这里能跑"的玄学问题。本篇用 uv 一次性解决。

## Python 版本

ML 生态对 Python 新版的支持总是滞后——被 PyTorch 等库的适配速度卡住。

- 选**你的关键库（尤其 PyTorch）已稳定支持**的版本，不盲目追新。
- **3.12 稳妥**；3.13 对主流 ML 库支持已基本就绪，可按需采用。
- 避开已停维的 3.8/3.9：无安全更新，新库不再测试。

```bash
python --version      # 查看当前版本（有些系统需用 python3）
```

macOS/Linux 自带的 `python3` 是系统 Python。直接装包会触发 PEP 668 "externally-managed-environment" 报错——这是系统保护自己，不是 bug。别碰系统 Python，用下面的 uv 装独立版本。

## uv：一个工具管好 Python + 包

[uv](https://docs.astral.sh/uv/)（Astral 出品，Rust 实现）作为本课程默认工具：装包比 pip 快一到两个数量级；同时管 Python 版本、虚拟环境、依赖、锁文件；`uv pip` 兼容 pip 接口；`uv.lock` 保证可复现。熟悉 conda 可继续用，但课程示例统一 uv。

```bash
# 安装
curl -LsSf https://astral.sh/uv/install.sh | sh          # macOS/Linux（跨平台统一，永远最新）
# Windows PowerShell: irm https://astral.sh/uv/install.ps1 | iex
uv --version

# macOS 用户建议用 Homebrew 安装：升级方便，随 brew update 自动跟进
# brew install uv

# 管理解释器（不依赖系统 Python，需要时自动下载）
uv python install 3.12      # 装 Python 3.12
uv python list              # 查看可用/已装版本
```

## 虚拟环境：每个项目一个隔离空间

虚拟环境让 A 项目用 NumPy 1.x、B 项目用 2.x 互不污染，不往系统装东西，依赖清单清晰便于复现。

```bash
uv venv                  # 当前目录创建 .venv（默认当前 Python）
uv venv --python 3.12    # 指定版本创建

source .venv/bin/activate        # 激活（macOS/Linux）
# .venv\Scripts\Activate.ps1     # Windows PowerShell
deactivate                        # 退出
```

激活后提示符出现 `(.venv)`，`python`/`pip` 指向环境内部。排查环境问题用 `which python`（macOS/Linux）确认指向项目 `.venv` 而非系统路径。uv 的 `uv run`/`uv sync` 会自动用项目 `.venv`，不必手动激活。

## 包管理：pyproject.toml 与锁文件

现代项目依赖声明在 `pyproject.toml`（项目元信息标准入口，依赖是其中一部分），而非传统 `requirements.txt`。四份文件各司其职：

| 文件 | 职责 | 是否入版本库 |
| --- | --- | --- |
| `pyproject.toml` | 声明需要哪些依赖及允许的版本范围 | ✅ |
| `uv.lock` | 锁定解析结果，含直接+间接依赖的精确版本与哈希 | ✅ |
| `.python-version` | 项目默认 Python 版本 | ✅ |
| `.venv/` | 本机实际安装的环境 | ❌ |

```bash
uv init ai-lab && cd ai-lab
uv python pin 3.12        # 写 .python-version
uv add numpy              # 写入 pyproject.toml 并锁定
uv add "pandas>=2.2"      # 版本约束
uv add --dev pytest       # 开发依赖（不进生产）
uv sync                   # 按 uv.lock 装齐依赖到 .venv
uv run python train.py    # 在项目环境运行（自动 sync）
```

`uv add` 做两件事：把依赖写进 `pyproject.toml`，更新 `uv.lock`。`uv.lock` 是复现关键——换机器 `uv sync` 拿到一模一样的环境。

严格一致性检查（CI/验收用）：

```bash
uv lock --check                   # 仅检查锁文件是否与配置一致
uv sync --locked                   # 不一致就失败，不自动改锁文件
uv run --locked python train.py    # 运行前同样校验
```

`--locked` 在配置与锁文件不一致时报错而非自动更新，适合 CI 和环境验收。临时试包不入项目依赖：`uv run --with requests python -c "import requests"`。导出传统清单：`uv export --format requirements.txt > requirements.txt`。

<Callout type="info">
用 `uv run` 执行脚本而非先 `activate` 再 `python`：自动确保环境最新同步，省掉"忘了 sync"。
</Callout>

## 完整流程：从零到能跑

```bash
uv init ai-lab && cd ai-lab
uv python pin 3.12              # 写入 .python-version
uv add numpy pandas matplotlib
# main.py: import numpy as np; print(np.array([1,2,3]).mean())
uv run python main.py           # 输出 2.0
```

项目结构：

```
ai-lab/
├── .python-version    # 解释器版本
├── .venv/             # 虚拟环境（不入版本库）
├── pyproject.toml     # 声明的依赖
├── uv.lock            # 精确锁定的依赖（入版本库）
└── main.py
```

`.venv/` 加进 `.gitignore`，`pyproject.toml` + `uv.lock` + `.python-version` 提交 Git。别人 clone 后 `uv sync` 即得一致环境——可复现落地。

## 换机器复现：锁文件管依赖，不管硬件

别人 clone 你的项目，不需要复制 `.venv`：

```bash
cd ai-lab
uv sync --locked        # 锁文件与配置不一致就失败
uv run --locked python main.py
```

但**锁文件只保证依赖解析一致，不保证跨平台运行一致**。macOS Apple Silicon、Linux x86_64、Windows 装的是不同二进制包；PyTorch/CUDA 还要看 GPU 驱动、CUDA 运行时、cuDNN 版本是否匹配。纯 Python 项目锁文件基本够用；涉及 GPU 训练/推理，必须额外记录并验证硬件与运行时——这部分留到深度学习与推理部署章节。

## 常见误区

- **直接用系统 Python 装包** → PEP 668 报错或污染系统。永远在虚拟环境里装。
- **只提交 requirements.txt 不提交锁文件** → 间接依赖版本漂移。提交 `uv.lock`。
- **`ModuleNotFoundError` 但装过** → 装到别的环境/没激活。用 `uv run` 或查 `which python`。
- **把 `uv add` 当 `pip install`** → `uv add` 改 pyproject.toml+锁文件（持久化）；临时装包用 `uv pip install`（不写配置）。
- **多版本 PyTorch 挤一个环境** → 不同实验开不同环境。
- **以为锁文件能保证所有平台跑出同样结果** → 锁文件管依赖解析，不管 OS/CPU/GPU/驱动。GPU 项目单独验证运行时。

## 小结

- 版本选生态兼容的稳定版（3.12 稳妥），用 uv 管 Python 版本+环境+依赖+锁文件一个不落。
- 复现三件套：`pyproject.toml` + `uv.lock` + `.python-version`，提交 Git。
- 锁文件管依赖解析，跨平台/GPU 一致性要单独验证。
