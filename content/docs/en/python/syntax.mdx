This assumes you already know how to code and just need to align Python's idioms and mental model fast enough to ship. The focus is what shows up most in ML work: mutable vs immutable, slicing, dicts and unpacking, `*args/**kwargs`, type hints, context managers — both the everyday bread-and-butter and the stumbling blocks you hit reading PyTorch/Pandas source. Not a from-zero tutorial; for obscure syntax consult the [language reference](https://docs.python.org/3/reference/).

## Variables & types: dynamically typed, but not typeless

A Python variable is a **name bound to an object**, not a slot holding a value. The type lives on the object; a name can rebind to a different type at any time — that's what "dynamic typing" really means.

```python
x = 1          # int
x = "abc"      # legal; x is now bound to a str
```

Core built-in types:

| Type | Example | Mutability |
| --- | --- | --- |
| `int` / `float` / `bool` / `str` | `1`, `3.14`, `True`, `"a"` | immutable |
| `tuple` | `(1, 2)` | immutable |
| `list` | `[1, 2]` | mutable |
| `dict` | `{"a": 1}` | mutable |
| `set` | `{1, 2}` | mutable |
| `NoneType` | `None` | singleton (immutable) |

**Mutable vs immutable is Python's biggest trap.** Argument passing, default arguments, copy semantics — nothing escapes it; see "Common pitfalls" below.

Numbers don't split into int/long: `int` grows to arbitrary size automatically, no overflow. `bool` is a subclass of `int` (`True == 1`). Strings are immutable — "modifying" a string actually builds a new one.

## Strings: f-strings and common ops

```python
name, n = "numpy", 3
f"{name} version {n}"          # 'numpy version 3'
f"{3.14159:.2f}"               # '3.14'  formatting
f"{n:>5}"                      # '    3' right-align
"; ".join(["a", "b", "c"])    # 'a; b; c'
"1,2,3".split(",")            # ['1', '2', '3']
"  hi  ".strip()              # 'hi'
"a;b;c".replace(";", "-")     # 'a-b-c'
```

f-strings are the preferred form — usually faster than `%`/`.format()`, and embedding expressions is clearer.

## Lists & slicing

Slicing is high-frequency in ML — NumPy/Pandas indexing both derive from it.

```python
a = [10, 20, 30, 40, 50]
a[0]          # 10     forward index from 0
a[-1]         # 50     negative index from the end
a[1:4]        # [20,30,40]  start inclusive, end exclusive
a[:2]         # [10,20]
a[2:]         # [30,40,50]
a[::2]        # [10,30,50]  step 2
a[::-1]       # [50,40,30,20,10]  reverse

a.append(60); a.pop()        # push / pop
a.extend([70, 80])           # in-place extend, avoid + (builds a new list)
```

Slicing is a **shallow copy**: `b = a[:]` gives a new list, but the elements themselves (if mutable) still share references. NumPy's basic slicing usually returns a **view** (mutating `b` changes `a`), while advanced (fancy) indexing returns a copy — confirm whether you hold a view or a copy before mutating, or data gets silently changed.

Python `list` and NumPy `ndarray` also differ in operator semantics — a key bridge from syntax into ML:

```python
import numpy as np
[1, 2, 3] * 2            # [1, 2, 3, 1, 2, 3]   list * repeats the sequence
np.array([1, 2, 3]) * 2  # array([2, 4, 6])      ndarray * is elementwise
```

Reading ML code, when you see `data * 2`, first confirm whether `data` is a list or an ndarray — same `*`, very different semantics.

Container comprehensions:

```python
[x*x for x in range(5)]                       # [0,1,4,9,16]
[x for x in nums if x > 0]                    # filter
{k: len(v) for k, v in model_cfg.items()}    # dict comprehension
{line.strip() for line in lines}              # set comprehension
```

Comprehensions suit simple transforms and filters — clearer than `for`-append in simple cases and usually more efficient (CPython has a dedicated bytecode), but for complex or deeply nested logic a plain `for` loop reads better. Don't reach for a comprehension just to be terse.

Swapping square brackets for parentheses gives a **generator expression** — lazy evaluation, yielding one item at a time without materializing the whole list:

```python
doubled = (x * 2 for x in range(1_000_000))   # no big memory footprint
total = sum(x * x for x in range(1000))       # feed straight into an aggregator
```

Large datasets and ML data loading rest on this idea (`range` is lazy the same way) — producing on demand rather than materializing all at once is the basis of streaming DataLoaders.

## Dicts, tuples & unpacking

Dicts are everywhere in ML: configs, hyperparameters, data samples, result records.

```python
cfg = {"lr": 1e-3, "epochs": 10, "model": "resnet"}
cfg["lr"]                    # fetch
cfg.get("batch", 32)         # missing key returns default 32 (no error)
cfg["weight_decay"] = 1e-4   # insert/update
del cfg["model"]             # delete
list(cfg)                    # ['lr','epochs','weight_decay']  iteration defaults to keys
for k, v in cfg.items(): ... # keys and values together
"lr" in cfg                  # True  key membership
```

From 3.7+ dicts **preserve insertion order** — configs and JSON results stay stable, which combined with lockfiles keeps experiments reproducible.

Tuples are immutable and used for fixed-structure records and multiple return values. Unpacking is the core idiom:

```python
shape = (3, 224, 224)
c, h, w = shape              # unpack
_, last = [1, 2, 3]          # ignore with _
first, *rest = [1, 2, 3, 4]  # rest = [2,3,4]  star collects

def minmax(seq):
    return min(seq), max(seq)   # returns a tuple
lo, hi = minmax([3, 1, 2])      # unpack directly
```

**Mutable default arguments are the classic trap**: the `[]` in `def f(x, items=[])` is created once and shared across calls, accumulating state. Use a `None` sentinel:

```python
def f(x, items=None):
    items = [] if items is None else items   # fresh each call
```

## Control flow

```python
if x > 0:
    ...
elif x == 0:
    ...
else:
    ...

for item in iterable: ...     # Python's for iterates, it isn't C-style counting
for i in range(5): ...        # 0..4
for i, v in enumerate(lst): ...   # index and value together
for a, b in zip(xs, ys): ...      # parallel iteration
while cond: ...
```

`range` is lazy and costs no memory. `enumerate`/`zip` are common for data alignment, but `zip` silently truncates to the shorter by default — when lengths should be equal, use `zip(xs, ys, strict=True)` (3.10+) to raise and surface the mismatch; to align to the longer, use `itertools.zip_longest`.

**Truthiness**: `if data:` / `if not data:` use an object as a boolean. Empty containers, `""`, `0`, `0.0`, `None` are all falsy; everything else is truthy.

```python
if not data:               # empty list / None / 0... all land here
    raise DataError("empty data")
```

Note that `0` is falsy too — `if not count:` mistakes a legitimate count of 0 for "no data". In counting/statistics contexts judge explicitly: `if count == 0:` or `if len(data) == 0:`.

`==` compares **value equality**, `is` compares **identity** (same object). Testing for `None` always uses `is None` (PEP 8), not `== None`. Small-int caching (`a=1; b=1; a is b` is `True`) creates the illusion that `is` works on values, but that's an implementation detail and unreliable across values.

## Functions: parameters, annotations & scope

```python
def train(X, y, lr=1e-3, epochs=10):
    ...

train(X, y, lr=1e-2)          # keyword args: clearer at the call site
train(X, y, epochs=5, lr=1e-2)  # keyword args may be reordered
```

`*args` collects extra **positional** args into a tuple, `**kwargs` collects extra **keyword** args into a dict. You'll see both in nearly every framework:

```python
def f(*args, **kwargs):
    print(args, kwargs)
f(1, 2, a=3)                  # (1, 2) {'a': 3}

def conv(in_ch, out_ch, *, bias=False, kernel=3): ...
# after *, only keyword passing works: conv(3, 64, True) errors, must conv(3, 64, bias=True)
```

A bare `*` in the parameter list forces the following args to be keyword-only — libraries use it to prevent positional mix-ups; it's standard in modern Python API design.

Forwarding kwargs is a common ML framework pattern — passing `**cfg` wholesale to a downstream constructor:

```python
def make_layer(cfg):
    return Conv(**cfg)         # expand the dict into keyword args
```

**Type hints** aren't enforced at runtime, but benefit the IDE, mypy, and anyone reading. Modern ML code (PyTorch, FastAPI) leans on them heavily:

```python
from typing import Optional

def load(path: str, split: float = 0.2) -> tuple[list, list]:
    ...

# 3.10+ syntax: list[int] | None replaces Optional/Union
```

Hints are "suggestions", not "contracts" — Python doesn't check them at runtime. For real validation use `pydantic` (you'll see a lot of it in FastAPI/RAG engineering).

**Scope**: an assignment inside a function defaults to creating a local. To rebind an outer name use `global`/`nonlocal` — but ML code mostly carries state through containers (dict/list) rather than touching `global`. LEGB lookup order: Local → Enclosing → Global → Built-in.

## Modules & imports

```python
import numpy as np                  # alias (community convention: np/pd/torch)
from torch import nn                # grab a submodule
from torch.nn import functional as F
from typing import Optional, List   # multiple names
```

Python has no real "private": a leading underscore (`_helper`) is a convention meaning "internal", still accessible; a double underscore `__name` triggers name mangling, not access control. Seeing `_xxx` in source means it's an internal and you shouldn't depend on it externally.

`__name__ == "__main__"` is the script-entry idiom — a file can both run directly and be imported without firing side effects:

```python
def main():
    ...

if __name__ == "__main__":
    main()
```

A package is a directory (modern Python allows omitting it, but a present `__init__.py` is clearest). `__init__.py` runs once when the package is imported and commonly aggregates exports: `from .sub import X` lets `import pkg` surface `pkg.X`.

## Exception handling

```python
try:
    data = load(path)
except FileNotFoundError:
    data = []
except (KeyError, ValueError) as e:   # catch several, bind the exception
    print(f"parse failed: {e}")
else:
    print("runs only if no exception")  # logic for the success path
finally:
    cleanup()                          # runs whether or not an exception occurred
```

- **Specific first**: list concrete exceptions (`FileNotFoundError`) before any broad fallback; only consider `Exception` as a last resort. A bare `except Exception:` swallows bugs you didn't anticipate, and you can't find the root cause while debugging.
- **Don't swallow**: `except: pass` is an anti-pattern. Even to ignore, use `except SpecificError: pass` with a comment on why.
- **Raising** uses `raise ValueError("msg")`; custom exceptions subclass `Exception` and form a hierarchy for precise catching.

```python
class DataError(Exception):
    pass

if len(data) == 0:
    raise DataError("empty dataset, cannot train")
```

<Callout type="info">
In ML debugging, a silently swallowed exception is deadlier than a crash — a training loop that catches one layer and `continue`s keeps running with NaN loss and you notice hours later. In data-processing code, prefer letting it blow up over hiding it behind a broad except.
</Callout>

## Files & context managers

The old way closes the file manually; forget and you leak a handle:

```python
f = open("data.txt", "r", encoding="utf-8")   # always specify encoding explicitly
text = f.read()
f.close()
```

`with` manages the resource and **closes on exit whether normal or exceptional** — this is the standard form:

```python
with open("data.txt", encoding="utf-8") as f:
    text = f.read()        # read all at once
    # or line by line
    for line in f:
        process(line.strip())
```

File modes: `r` read / `w` truncate-write / `a` append / `x` create-if-absent. Text adds `t` (default), binary adds `b` (for images, model weights, etc.). `encoding="utf-8"` should be explicit across platforms — the default encoding varies by system locale, Python version, and UTF-8 mode, so specifying it avoids depending on the runtime environment.

`pathlib` is the modern choice for path operations, clearer than `os.path` string concatenation:

```python
from pathlib import Path

root = Path("data/raw")
for p in root.glob("**/*.csv"):   # recursively find all csv
    print(p.name, p.stem, p.suffix)
out = Path("out") / "result.json"  # / joins paths, cross-platform
out.parent.mkdir(parents=True, exist_ok=True)  # mkdir -p
```

JSON and CSV are the most common formats ML data crosses:

```python
import json, csv

with open("cfg.json", encoding="utf-8") as f:
    cfg = json.load(f)            # parse into dict/list
with open("out.json", "w", encoding="utf-8") as f:
    json.dump(result, f, ensure_ascii=False, indent=2)  # ensure_ascii=False keeps non-ASCII

with open("data.csv", encoding="utf-8") as f:
    for row in csv.DictReader(f):   # each row becomes a dict, keyed by header
        process(row["label"])
```

**Context managers aren't only for files.** Any object with `__enter__`/`__exit__` works with `with`; typical ML examples: `with torch.no_grad():` disables gradients, `with torch.cuda.amp.autocast():` enables automatic mixed precision, `with wandb.init(...) as run:` manages an experiment run. Read `with` as "enter a state, guarantee restoration on exit" — files are just the simplest case.

## Common pitfalls

- **Mutable default arg** `def f(x, lst=[])` → the same list is shared across calls. Use `lst=None` sentinel.
- **Using `is` as `==`** → `is` is only for `None`/`True`/`False` or explicit identity checks; compare values with `==`.
- **Mistaking shallow copy for deep copy** → `b = a` only rebinds; `b = a[:]` is shallow; for full independence use `copy.deepcopy`.
- **`except Exception: pass` swallowing** → hides bugs, especially deadly in ML training. Catch specifically, at least log.
- **`open` without `with`** → leaks file handles along exception paths; always `with open(...)`.
- **Forgetting `encoding="utf-8"`** → the default varies across platforms; reading non-ASCII without it eventually corrupts text.
- **Unnoticed `zip` truncation** → silently drops data when lengths differ; for should-be-equal cases use `zip(..., strict=True)` (3.10+) or `itertools.zip_longest`.
- **Mixing `*args`/`**kwargs` order** → parameter order must be: positional → `*args` → keyword-only → `**kwargs`; keyword-only args after `*` can't be passed positionally.
- **Treating type hints as runtime checks** → hints are suggestions, not enforced; for validation use `pydantic` or `beartype`.

## Summary

- Dynamic typing ≠ typeless; mutable/immutable is the biggest trap, and default args and copying both run into it.
- Slicing, dicts, unpacking, `*args/**kwargs`, and type hints are the baseline for reading ML framework source.
- Truthiness (`if not data:`) is handy but `0`/`None`/empty containers are all falsy — don't misjudge in counting contexts; lazy generator expressions are the basis of streaming data loading.
- Catch exceptions specifically and never swallow them silently; use `with` for files and resources, and always specify `encoding` explicitly.
- `is` tests identity, `==` tests equality, and `None` is always tested with `is None`.
